# Moderator run-sheet

## Before participants arrive

1. Use a private/trusted network and the rehearsed server build. Connect the server to power, prevent sleep, check free disk space and confirm a restorable backup. Start one server, not concurrent dev/production instances.
2. Open the moderator site using the LAN/HTTPS address participants will use, log in, create/select the project and session, and verify the session name. Keep this moderator tab connected throughout active runs.
3. Upload the exact H.264/AAC MP4 to be shown. Confirm duration, title, review playback and audio. Set Shared Screen or Individual Tablet Mode; save the question, endpoints, optional reaction button and optional group tags.
4. Prepare a **Practice** viewing first. Explain: 0–100, initial score 50, keep the slider where it reflects the current reaction, continuously sampled even if untouched; the optional reaction button records individual presses.
5. Shared Mode: open the private shared-display link on the central display and check it shows no ratings/results. Individual Mode: fit headphones, confirm audible volume and keep the slider accessible in the chosen orientation.

## Join and readiness

1. Show the public join QR/code. Confirm each tablet has one distinct anonymous ID and the intended group tag. Do not open the same credential on two devices/tabs.
2. Have tablets disable auto-lock if Wake Lock is unavailable. Explain that they must keep the page visible. Check connection, visibility and storage messages; address every warning.
3. Prepare the selected viewing. Each included tablet taps Ready; the shared display or individual video players also verify real playback/buffering. Wait for **Ready** in the monitor; pressing a button alone is not sufficient.
4. If readiness times out, inspect video encoding, network and storage, wait for buffering and retry Ready. Never start by bypassing a failed readiness check. Lock entry when the intended group is present.

## During each recording

1. For actual research, end practice and prepare a new viewing **without** the Practice checkbox. Confirm a new run ID, correct clip/mode/question and every included device ready.
2. Click Start; allow the scheduled start to reach all devices. Observe the real display and device monitor. Do not navigate away from the moderator page during a run.
3. If paused automatically or manually: explain that collection is stopped, inspect the reason, and let media devices align while paused. Every included device taps Ready again. Exclude an unavailable identity explicitly if necessary; document the reason in your research notes.
4. Resume only after readiness returns. Do not manually seek, change playback speed, refresh the display or rotate credentials during active recording. A correction while paused is logged.
5. If the server stops/restarts, treat the run as interrupted. Preserve its data and create a separate new viewing; never relabel it as a continuous uninterrupted run.

## Close and report

1. End the viewing and keep tablets awake/connected until pending uploads reach zero and final capture counts reconcile. Investigate provisional reports and explicitly disclose any unreconciled device or coverage gap.
2. Review the correct run, question and research/practice status. Check flags, participant/group selection and opening exclusion before interpreting peaks or shifts. A statistical shift is a change in the selected rating measure, not inferred persuasion/attention.
3. Export raw ratings/reactions, filtered statistics/key moments and the chart PNG as needed. Save a session JSON archive (no media/credentials) and a full database/media backup. Verify a restore rehearsal on a copy before retiring the installation.
4. Log out, stop the server after all runs/queues are settled, and retain research materials under your organisation’s access/retention policy.
